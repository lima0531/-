# 旧库详情原响应与逐次收据

每条记录按固定队列位置和真实 `applyId` 建立文件名。每次尝试保存原始响应字节及收据；网络层没有得到响应正文时，仅有收据，不能伪造空白成功响应。截断响应如能取得部分原字节，会标记 `response_body_is_partial`，不作为成功缓存。

成功取值必须通过 HTTP 200、原字节 SHA256 与长度、业务结果 1、详情对象和精确型号回显校验。详情中的备案号或 applyId 若非空也必须与来源记录一致；实际为 null 的回显另记事实。失败尝试保留，不用“能解析 JSON”作为成功标准。

本轮首 100 条全部取得正常 HTTP 200 原响应与对应收据，共 100 份原响应 JSON、100 份收据 JSON；原响应合计 157,840 字节。无失败尝试，没有旧库 PDF 标签文件。实际数量和进度以父目录 `checkpoint.json` 与 `archive_review_summary.json` 为准。
