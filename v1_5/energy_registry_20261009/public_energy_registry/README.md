## 实际数据质量问题

1. **分页参数曾无效。**`pageNum=2`回显仍为1，且与第一页原字节相同，错误枚举在第2页停下。原响应保存在`new/page0001_response.json`、`new/page0002_response.json`，原停机状态为[failed_pageNum_checkpoint](failed_pageNum_checkpoint.json)。随后采用官方前端`currentPage`，分别以真实第2页作验证。
2. **UUID不是完整行的唯一键。**新库第2页3组相同UUID/备案号分别有不同`abandonTime`（2026-08-06/2026-08-11），确实是不同状态行；保留800行而非删成797条。[重复标识剖面](重复标识_状态版本差异_不得删除.csv)列差异字段；初版唯一ID假设的停机状态也保留，未把它当数据缺失。
3. **筛选与行类别存在矛盾。**旧第10页中`ART5010TSLS09BEV`返回`reportType=1`，其余199行为3。[矛盾原行定位](筛选视图_响应分类冲突_原行保留.csv)单列；不凭BEV后缀认证纯电，也不删除该原行。这不影响来源视图行数对账，却限制类别解释。
4. **新旧记录不可直接合并。**JX定向旧详情电耗22.8，新标签19.2；质量和续航同值并不能证明同测试、同电池或同税配置。旧`publicTime`是月精度原字段，新`issueDate`是语义尚未核实的原字段，各自保存。

本轮已观察的新库目标行中未发现可用的非空检测报告下载引用，这仅适用于已取4页，不据此否定其余49页。标准代码没有无依据映射；旧列表工况代码与旧详情/新PDF的字面标准证据分别处理。
