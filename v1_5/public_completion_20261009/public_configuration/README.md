## 实际检索范围及没有闭合的原因

工业和信息化部原生正文索引对36个完整型号各请求一页，均HTTP 200、接口登记total=0；同时用完整同参数查询已知“新能源汽车推广应用推荐车型目录 2022年第12批”，返回两个真实主管公告，阳性对照有效。记录见[36完整结果](36模型_工信部原生检索完整结果.json)及[阳性对照](search/positive_control_recommendation_2022_12.hits.json)。这一结果只说明本次正文索引没命中；型号常只存在附件中，不能据此说参数附件、企业档案或互联网都不存在资料。

DuckDuckGo另外定向查看8个多值/交叉型号。前5个只发现商业公告镜像、行业协会税录转载等候选；后三个（YGM7000BEVBD1、TV6470BEVFFE、JNJ7000EVM1）实际返回验证页，没有继续。详细[候选及来源](8型号_相关外部索引候选.csv)。结果标题精确含型号仅是发现线索，不是科学原件或配置身份认证。Bing另一路实际响应普遍是不相关内容，整路已排除为有效证据；保留原响应和相关性审查，**未将0相关项当成不存在资料**。

36与既有285版本只交叉2型号、3版本：`CC7000CG00FBEV`的NC017525，`GTM6470BFEBEV`的NC016953和NC016943。已保存的2022年第4批推荐声明与税54批原值分别有配置ID和多值/公差，但税申报原表没有这几个NC配置ID。协会两页仍是同税54批数值重复，没有新的配对表或报告编号，见[逐页审查](两个交叉型号_协会转载核查.json)。不能用同型号、同续航、近似整备或计算结果吻合代替跨目录同配置证明。

装备中心真实首页给出产品公告综合查询与能源消耗量查询路径。新service查询页本次403、旧app页502；能源官网首页和公开前端取得200实质响应，前端明确普通/高级查询先弹滑块验证且默认不请求车型列表。本轮未绕过验证、未请求任何车型结果，因此仅提供本人可试的入口和保存说明。标签若拿到，仍需区分能耗配置ID、推荐NC ID和税目录申报版本。

## 何时可以关闭

36型号：带具体申报版本/配置ID的电池能量、质量配对，斜线选项和公差定义，原试验报告编号、工况和日期。32型号用于判断联合门槛；4型号的联合不满足已经确定，只在要细分单项时找。材料若继续多配置，保留多配置结果，不保证变成单值可用。

285身份版本：每个NC配置与税目录具体申报配置之间的正式对应文件，并核对电池系统、电机和报告版本。原申报整车企业技术/认证部门或原检测机构是下一材料持有人。后于2023-12-10的来源不回填冻结输入；后来取得的历史私档可以证明历史技术事实，但要进入公告前信息集，还须另核当时的信息可得性。

本轮是有界公开探查的收尾，未声称穷尽互联网。主科学文件没有写入，36旁证仅按既定record_id选取并保留完整上游指纹。没有新有效材料时不再重复同样网页轮次；本人官网取得标签或企业给出原申报/报告后，再逐件核验。

## 重跑

需要Python、pandas和lxml，联网采集保持TLS校验。原响应有收据时优先复用缓存，避免重复请求。`external_discovery.py`为已判不相关的Bing路径历史脚本，不属于推荐重跑步骤。

```bash
python collect_public_configuration.py
python replay_public_routes.py
python targeted_ddg_discovery.py
python build_configuration_status.py
```

36参数旁证及3份材料清单已随本目录保存。构建脚本仅在旁证未存在时才从默认本地主科学路径选取36记录；主科学输入存在时检查原SHA不变。本轮10项核对通过；文件清单不含自身和Python缓存。
